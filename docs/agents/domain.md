# Domain docs

This repository uses a single-context domain documentation layout:

- `GLOSSARY.md` at the repository root.
- Architecture decision records under `docs/adr/`.

Before exploring a topic, read the glossary and any relevant ADRs if
they exist. If they don't exist, proceed without creating them upfront;
domain-modeling can create them when decisions or terms are resolved.

Use the glossary's established vocabulary. If a proposal contradicts
an ADR, surface the conflict explicitly rather than silently overriding
the decision.
